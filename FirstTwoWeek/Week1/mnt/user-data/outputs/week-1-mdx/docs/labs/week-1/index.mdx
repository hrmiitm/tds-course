# Week 01 — Hands-on Labs

The three Week 1 labs are designed to **ship things to the internet**. By the end of the week you will have:

1. A real, installable Python package published on **PyPI**.
2. A command-line tool + a LaTeX-rendered PDF hosted on **GitHub Pages**.
3. A **cron-scheduled Bash script** that auto-commits daily project summaries to GitHub.

Each lab is structured as a sequence of **collapsible steps** — click a step to expand it. Don't skip around; the steps build on each other. All steps include the exact commands to run and the exact files to create.

## The Labs

| # | Lab | What you'll build | Time |
|---|-----|-------------------|------|
| 1.1 | [Publish a Python library to PyPI using UV](./publish-python-library-pypi-uv.mdx) | A real Python package installable via `pip install your-package`, published with GitHub Actions + Trusted Publishing | 60–90 min |
| 1.2 | [UV CLI tool + LaTeX docs PDF on GitHub Pages](./uv-cli-tool-latex-docs.mdx) | A `uvx`-installable CLI; auto-generated PDF docs deployed to GitHub Pages | 60–90 min |
| 1.3 | [Bash automation — daily project summary](./bash-daily-project-summary.mdx) | A cron-scheduled Bash script that generates a daily digest of your Git activity and commits it | 45–60 min |

## Prerequisites

Before starting any lab, make sure you can answer **yes** to all of these:

- [ ] I have UV installed (`uv --version` works).
- [ ] I have a GitHub account and SSH or `gh auth login` set up.
- [ ] I have a [PyPI account](https://pypi.org/account/register/) (required for Lab 1.1).
- [ ] I have a [Test PyPI account](https://test.pypi.org/account/register/) (separate from PyPI, required for Lab 1.1).
- [ ] I have Python 3.11+ on my machine (`uv python list` will show what's installed).
- [ ] I have `gh` CLI installed and authenticated.

If any of these are missing, complete them first.

## Grading

These labs are **non-graded but essential**. Two course TAs complete and document canonical implementations of each lab — browse their repos for reference. Your Discourse blog posts about what you built are what get indexed on the course portal.

## Tips for Success

:::tip Read the whole lab first
Skim every step before starting. Labs have a structure — knowing where you're going prevents detours.
:::

:::tip Copy, paste, and then actually read
Every command block is meant to be pasted. But pause after each one and read the output. That's where the learning happens.
:::

:::tip When you get stuck, bisect
If something breaks, comment out the last change and confirm things still work before it. Git is your friend here — commit after every working step.
:::

:::warning Don't share secrets
Lab 1.1 briefly discusses PyPI tokens. Never paste tokens into public repos, issue trackers, or Discourse. When in doubt, assume anything you share is public forever.
:::
